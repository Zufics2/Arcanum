# Arcanum

Arcanum - это облачное хранилище, в котором сервер не может прочитать ваши файлы. Всё шифруется прямо в браузере ещё до отправки, поэтому на сервер попадает только набор случайных байтов. Ни содержимого, ни имён файлов и папок, ни пароля сервер не знает.

## Что умеет

- Регистрация по логину и паролю, без почты и телефона.
- Загрузка файлов до 200 МБ, папки, переименование, перемещение, удаление.
- Предпросмотр картинок, PDF, видео, аудио и текста без скачивания.
- Поиск по именам во всём диске. Он работает в браузере, поэтому запрос на сервер не уходит.
- Ссылки для обмена файлами со сроком жизни и лимитом скачиваний. После последнего скачивания ссылка удаляется сама.
- Режим «Глазами сервера»: можно посмотреть, как ваши файлы на самом деле лежат на сервере.
- Ключ восстановления на случай, если забыли пароль.
- Профиль с аватаркой, смена пароля, квота хранилища, удаление аккаунта.
- Несколько аккаунтов в одной вкладке, светлая и тёмная тема.

## Как работает шифрование

Используется только встроенный в браузер Web Crypto API, без сторонних библиотек.

```
пароль + соль ──PBKDF2──► authHash   (уходит на сервер вместо пароля)
              └─PBKDF2──► userKey    (остаётся в браузере)

userKey   шифрует masterKey  (случайный ключ пользователя)
masterKey шифрует fileKey    (свой ключ у каждого файла)
fileKey   шифрует содержимое и имя файла
```

Все ключи живут только в памяти вкладки. После перезагрузки страницы их нет, поэтому нужно ввести пароль ещё раз. Сессия при этом сохраняется: вместо полной формы входа появляется экран разблокировки.

Ссылка для обмена выглядит так: `https://сайт/s/{id}#{ключ}`. Часть после `#` браузер никогда не отправляет на сервер, так что сервер отдаёт зашифрованный файл, но открыть его не может.

Что сервер всё-таки видит: сколько у вас файлов, их размеры, время загрузки и то, как устроены папки. Это видно и в режиме «Глазами сервера».

## Стек

- **Фронтенд:** Next.js (App Router, TypeScript), React, Ant Design, TanStack Query, Zustand, axios, dayjs
- **Бэкенд:** Django, Django REST Framework, SimpleJWT, drf-spectacular
- **База данных:** PostgreSQL
- **Инфраструктура:** Docker Compose, nginx

## Быстрый старт через Docker

Нужен установленный Docker Desktop.

```bash
cp .env.example .env
```

В `.env` достаточно задать `SECRET_KEY` и `POSTGRES_PASSWORD`. Ключ можно сгенерировать так:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(50))"
```

Потом запускаем:

```bash
docker compose up --build
```

Приложение откроется на http://localhost, документация API на http://localhost/api/docs/.

Остановить можно командой `docker compose down`. Данные при этом сохраняются. Флаг `-v` удалит их вместе с контейнерами, так что с ним осторожно.

## Локальная разработка

Понадобятся Python 3.13, Node.js 24 и PostgreSQL.

**Бэкенд.** В `.env` укажите `DEBUG=True` и `DATABASE_URL` с хостом `localhost`, например `postgres://arcanum:пароль@localhost:5432/arcanum`.

```bash
cd backend
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

**Фронтенд.** Создайте `frontend/.env.local` со строкой `NEXT_PUBLIC_API_URL=http://localhost:8000/api`.

```bash
cd frontend
npm install
npm run dev
```

Сайт будет на http://localhost:3000. Если меняли `.env.local`, перезапустите `npm run dev`, иначе Next.js не увидит новые значения.

## Показ через туннель

Шифрование в браузере работает только по HTTPS (или на localhost). Чтобы показать проект с другого устройства, удобно использовать бесплатный туннель Cloudflare. Регистрация для него не нужна.

```bash
brew install cloudflared   # один раз
./scripts/demo.sh
```

Скрипт поднимет контейнеры, дождётся бэкенда и откроет туннель. В выводе появится адрес вида `https://какие-то-слова.trycloudflare.com`, его можно открыть хоть с телефона.

Пара вещей, которые стоит знать:

- Адрес меняется при каждом запуске и работает, пока открыт туннель.
- Зарегистрироваться может любой, у кого есть адрес. После показа лучше закрыть туннель через `Ctrl+C`.
- Если ноутбук уснёт, туннель оборвётся. На время показа можно запустить `caffeinate -d` в соседнем терминале.
- Если сеть блокирует туннель, попробуйте `cloudflared tunnel --protocol http2 --url http://localhost:80`.
- Большие файлы через туннель лучше проверить заранее. Сторонние источники пишут, что Cloudflare может ограничивать запросы примерно сотней мегабайт.

## Тесты

```bash
cd backend && pytest     # API, права доступа, удаление файлов с диска, ссылки, восстановление
cd frontend && npm test  # криптография
```

Тесты криптографии сверяют результат с эталонными значениями PBKDF2, HKDF и base32, посчитанными отдельно на Python. Так видно, что браузерная часть шифрует ровно так, как задумано.

Перед коммитом во фронтенде стоит прогнать ещё `npm run lint` и `npm run build`.

## Ограничения

Об этом честнее сказать сразу:

- Если забыть пароль и не создать ключ восстановления, файлы вернуть нельзя. Никто, включая администратора, их не расшифрует. Это не баг, а сама суть подхода.
- Файл шифруется целиком в памяти браузера, поэтому есть лимит в 200 МБ.
- Метаданные (количество файлов, размеры, даты, структура папок) сервер видит.
- Если отозвать ссылку, новые скачивания станут невозможны, но тот, кто уже скачал файл, сохранит его.

## Приватность

Проект не собирает почту и телефон, не пишет IP-адреса в логи и не подключает аналитику или сторонние скрипты. Даже Swagger UI раздаётся с собственного сервера, а не с CDN.
